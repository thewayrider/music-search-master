================================================================================
TWO-STAGE RELEASE VERIFIER — USER & FLEET MANUAL
================================================================================

The Two-Stage Release Verifier is an autonomous validation pipeline designed
to ensure newly discovered tracks are:
1. Originating from target territories: Australia (AU), New Zealand (NZ), or Ireland (IE)
   (also supports United States 'US' or 'GLOBAL' discovery).
2. Genuine new releases first published within a 14-day window (filtering out
   remasters, reissues, anniversary editions, and older album tracks).

--------------------------------------------------------------------------------
HOW IT WORKS UNDER THE HOOD
--------------------------------------------------------------------------------

STAGE 1: DETERMINISTIC FAST SIEVE (Sub-millisecond / 0 MB RAM)
- Immediately verifies items from single-region channels (Triple J Unearthed,
  Triple J, AMRAP, Air Charts, Roots Mag NZ, Nialler9) if published within the
  freshness window.
- Immediately rejects items containing reissue/catalog keywords in title or
  metadata ("Remaster", "Anniversary Edition", "Reissue", "Live at", "Demo 199*").
- Passes ambiguous items to Stage 2.

STAGE 2: DUAL-SAFETY AGENT VERIFICATION
- Priority 1 (Local Ollama): If Ollama is running at http://localhost:11434,
  it executes a fast tool-calling agent loop (qwen2.5:3b, num_ctx: 2048, capped at 3 turns).
- Priority 2 (Cloud Fallback): If Ollama is offline or uninstalled, it seamlessly
  falls back to Gemini Flash using your existing configs/secrets.json. Tools
  (MusicBrainz & iTunes) run in Node.js first, sending ground truth to the API in ~1s
  with ZERO local RAM consumed.
- Tool Helpers Used:
  * MusicBrainz: Checks artist origin, including Indigenous places (Naarm, Meanjin,
    Gadigal, Tāmaki Makaurau, etc.) with a 1.1s rate-limiting queue.
  * iTunes Search: Checks historical release dates to catch older cuts.
  * Clue Inspector: Scans blurbs and URLs for city demonyms and reissue tags.

================================================================================
PRACTICAL WAYS TO RUN THIS
================================================================================

METHOD 1: ONE-CLICK INTERACTIVE MENU (EASIEST)
Simply double-click:
  run_verifier.bat

This opens an interactive menu that lets you:
  [1] Run the unit test suite (5 mock releases).
  [2] Verify an existing saved search JSON file.
  [3] Run the Bandcamp crawler with verification.
  [4] Run the AMRAP crawler with verification.
  [5] Run the Air Charts crawler with verification.

--------------------------------------------------------------------------------
METHOD 2: COMMAND LINE (POWERSHELL / TERMINAL)

1. Run the Test Suite:
   node testVerifier.js

2. Verify a Crawler Job with the --verify Flag:
   node src/index.js configs/bandcamp_indie.json --verify
   node src/index.js configs/amrap_indie.json --verify

   *What happens:* Newly discovered songs are verified before being saved to
   JSON, HTML reports, SQLite catalog, or email alerts. Reissues and non-target
   acts are automatically filtered out.

3. Verify an Existing Saved Search File:
   node src/index.js --verify saved_searches/amrap_indie_discovery/amrap_indie_discovery_base.json

--------------------------------------------------------------------------------
METHOD 3: AUTOMATED SCHEDULING (MINI PC / TASK SCHEDULER)

To enable automatic verification on your scheduled crawlers on the Always-On Mini PC:
Edit any crawler command or batch file (e.g. run_crawlers.bat) to include --verify:
  node src/index.js configs/bandcamp_indie.json --verify

Because of the dual-safety fallback, the Mini PC will run smoothly whether or not
Ollama is running locally.

================================================================================
CONFIGURATION & ENVIRONMENT VARIABLES
================================================================================

All settings have sensible defaults and can be customized via environment variables:

  OLLAMA_BASE_URL      Default: http://localhost:11434
                       (Can point to a Tailscale IP like http://100.x.y.z:11434)
  OLLAMA_MODEL         Default: qwen2.5:3b
  RELEASE_WINDOW_DAYS  Default: 14

Target regions can be specified in crawler configs or script options:
  - ['AU', 'NZ', 'IE'] (Default: Australia, New Zealand, Ireland)
  - ['US']             (United States tastemaker scope)
  - ['GLOBAL']         (Bypasses origin filter; verifies genuine new release only)
